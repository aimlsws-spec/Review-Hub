# README_DATABASE.md — ReviewHub Database Architecture

## Overview

ReviewHub uses **MySQL 8.0+** managed via **Prisma ORM**. The schema is organized into 7 domain batches, each independently maintainable.

## Migration Process

```bash
# Generate a new migration
npx prisma migrate dev --name <migration_name>

# Apply migrations in production
npx prisma migrate deploy

# Reset database (dev only — DESTRUCTIVE)
npx prisma migrate reset

# Check migration status
npx prisma migrate status
```

> Always run `npx prisma generate` after schema changes to regenerate the Prisma Client.

## Seed Process

```bash
# Install dependencies first
npm install

# Run seed
npx prisma db seed

# Or directly
npx ts-node prisma/seed.ts
```

Add to `package.json`:
```json
{
  "prisma": {
    "seed": "ts-node prisma/seed.ts"
  }
}
```

Seed creates:
- 4 system roles (super-admin, admin, merchant, user)
- 21 permissions with role assignments
- Super Admin + Default Admin users
- 3 countries, 4 states, 5 cities
- 5 notification templates
- 8 system settings
- 6 feature flags
- 3 AI providers (Ollama, Bedrock, OpenAI-compatible)
- 7 campaign categories
- 6 FAQs
- 1 platform configuration record

## Naming Conventions

| Element | Convention | Example |
|---|---|---|
| Table names | snake_case, plural | `campaign_participants` |
| Column names | camelCase in Prisma, snake_case via `@map` | `merchantId` → `merchant_id` |
| Relation names | PascalCase string literals | `"CampaignAuditUser"` |
| Enum values | SCREAMING_SNAKE_CASE | `PENDING_VERIFICATION` |
| Index names | Auto-generated by Prisma | — |

---

## Index Strategy

- Every foreign key column has a dedicated `@@index`
- High-cardinality filter columns indexed: `status`, `createdAt`, `deletedAt`
- Composite indexes for common query patterns: `[userId, type, status]` on `otps`
- Unique constraints used for natural keys: `[merchantId, accountNumber, ifscCode]`
- `@@unique` on business keys: `slug`, `email`, `key`

---

## Soft Delete Strategy

Every domain model includes `deletedAt DateTime?`.

- Soft delete: `UPDATE ... SET deleted_at = NOW() WHERE id = ?`
- All queries must filter `WHERE deleted_at IS NULL`
- Hard delete only for: `otps`, `login_history`, `analytics_events`, `audit_logs`, `activity_logs` (append-only / time-series)
- Prisma middleware recommended to auto-filter `deletedAt: null`

---

## UUID Strategy

- All primary keys: `String @id @default(uuid())` — UUID v4
- Exception: `AdminUser` uses `cuid()` (legacy, can be migrated)
- UUIDs are generated at the application layer by Prisma, not the database
- MySQL stores UUIDs as `VARCHAR(36)` (Prisma default)
- For high-throughput tables, consider `CHAR(36)` or binary UUID optimization

## Backup Recommendations

| Frequency | Method | Retention |
|---|---|---|
| Continuous | MySQL binlog replication to read replica | Real-time |
| Hourly | Automated RDS snapshots (if AWS RDS) | 7 days |
| Daily | Full mysqldump to S3 with encryption | 30 days |
| Weekly | Cross-region S3 replication | 90 days |
| Monthly | Glacier archive | 1 year |

```bash
# Manual backup
mysqldump -u USER -p viral_kar_prod --single-transaction --routines --triggers > backup_$(date +%Y%m%d).sql

# Restore
mysql -u USER -p viral_kar_prod < backup_20240101.sql
```

## Environment Setup

Copy `.env.example` to `.env` and configure:

```bash
cp .env.example .env
```

Minimum required for local development:
- `DATABASE_URL` — MySQL connection string
- `JWT_ACCESS_SECRET` / `JWT_REFRESH_SECRET` — min 32 chars
- `REDIS_HOST` / `REDIS_PORT` — Redis connection
- `OLLAMA_BASE_URL` — for AI verification (or disable via feature flag)
